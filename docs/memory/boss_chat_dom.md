# BOSS 消息页 DOM 专项记忆

> 详细来源：`docs/boss_chat_dom_notes.md`。本文件只保留长期有效结论，供消息页 DOM 调研和插件集成窗口快速读取。

更新时间：2026-08-02

## Fact

- BOSS 消息页登录态路径是 `/web/geek/chat`，点击不同会话时 URL 可能不变，不能只靠 URL 判断当前会话。
- 当前会话必须从左侧会话列表的选中态和右侧聊天详情 DOM 综合判断。
- 消息列表需要尽量采集：HR 名称、HR 角色、公司名、岗位名、薪资、城市、最新 HR 消息、未读状态、最近时间、职位入口。
- 聊天详情页需要尽量采集：最近对话上下文、最后一条 HR 消息、输入框、发送按钮状态。
- “查看职位”会跳到类似 `/job_detail/<job_id>.html?securityId=...` 的岗位详情页，可作为后续补完整 JD 的入口。
- 第一版 HR 回复助手不强制补完整 JD，优先使用已有岗位缓存和消息页能读到的 `job_detail_entry`。
- 当前候选输入框是 `#chat-input[contenteditable='true']`，发送按钮候选是 `.chat-op .btn-send`。

## Decision

- 插件不能依赖聊天页 URL 变化来定位会话。
- 第一版只采集有限上下文，不读取整页文本和完整历史聊天。
- 第一版只填回复草稿，不自动发送。
- 海投运行中发现 HR 回复，只加入待回复队列和提醒用户，不跳转聊天页。

## Constraint

- 不能在海投运行中抢当前搜索页。
- 不能在未确认会话归属时填输入框。
- 不能点击发送按钮。
- 如果关键 DOM 缺失或会话定位不可靠，应提示用户接管，而不是继续自动化。
- 所有真实公司、HR、聊天内容、岗位链接截图都必须打码后才能写入文档或提交。

## Risk

- `.notice-badge`、`.dot` 等未读标记 selector 仍需真实 BOSS 登录态复测。
- 会话选中态 selector 可能随 BOSS 改版变化。
- 输入框激活和填入方式可能受焦点、富文本编辑器事件影响。
- “查看职位”入口可能不是稳定 href，也可能需要点击后异步加载。
- 切换会话后 URL 不变，容易出现“队列项 A 但右侧仍是会话 B”的错填风险。

## Open Question

- 未读会话最稳定的 DOM 标记是什么。
- 左侧会话 item 是否存在稳定的会话 ID 或岗位 ID。
- 点击“查看职位”后是否能稳定回到原聊天会话。
- BOSS 是否会对频繁消息页扫描触发风控。
