# 求职加速器项目地图

> 用途：这是多窗口协作的热记忆地图，只放当前方向、全局硬约束、记忆路由和下一步。它不是流水账，也不保存真实 API Key、访问令牌、朋友包 token、完整简历、真实 HR 聊天内容或未打码截图。

更新时间：2026-08-03

## 当前主线

求职加速器是面向 BOSS 直聘的 Chrome 插件，第一版定位是“小而美的求职效率工具”。

当前核心目标：
- 岗位页：用户先在 BOSS 设置城市、岗位、薪资、经验、学历等筛选条件，插件负责读 JD、匹配简历、达标后自动点击“立即沟通”和“留在此页”，继续处理下一条。
- 消息页：HR 回复助手和海投功能集成在同一个插件里，先发现新回复并加入待处理队列，用户点击“处理回复”后才进入消息/聊天页生成回复草稿。
- 可观测：插件侧边栏要能看见当前页面模式、任务、进度、最近一步、下一步建议和调试状态，减少“卡住但不知道卡在哪”的问题。
- 后端：普通用户不需要本地跑 Python、不需要自己配置 API；朋友版默认走云端后端。

## 全局硬约束

- 只做一个 Chrome 插件，不做两个互不知状态的插件。
- 同一个 BOSS tab 同一时间只能执行一种页面操作，必须有全局 task lock。
- 页面操作优先级：用户手动操作 > HR 回复处理 > 海投扫描。
- 海投运行中，回复助手只能记录待回复队列和提醒用户，不能抢当前搜索页、不能跳转聊天页、不能填输入框。
- 用户主动点击“处理回复”后，才允许暂停海投、进入消息/聊天页、调用 `/chat/reply` 并填入草稿。
- HR 回复助手只填草稿，不自动点击发送按钮。
- 快速投递必须不依赖 LLM；智能投递和 HR 回复可以调用 LLM，但超时、忙碌、失败时必须兜底，不能卡住主流程。
- 状态可观测面板只能展示状态，不改变业务流程，不能新增自动发送能力。
- BOSS 原生筛选条件仍由用户在 BOSS 页面设置，插件里的关键词/排除词只是兜底过滤，不替代 BOSS 筛选。
- 开源前必须清理 `.env`、`release/`、真实截图、真实 token、真实 API Key 和未打码日志。

- 窗口 3：聊天消息提取已放宽为不依赖 `data-mid`，并增加消息节点、HR 消息、本人消息和文本消息四项只读诊断计数；仍待真实登录态复测确认。

## 当前不做

- 不做无人值守自动发送 HR 回复。
- 不绕过登录、验证码、MFA 或平台风控。
- 不保存用户 BOSS 密码。
- 不把真实简历、真实聊天记录、API Key、访问令牌写进仓库。
- 不让多个分支窗口同时改 `plugin/content.js`、`server.py`、`pipeline.py`。
- 不在 HR 回复里主动承诺薪资、到岗、报价、远程交付或替用户输出超长完整面试答案。
- 不接入 `energypantry/agent-browser-runtime` 作为当前版本依赖；它只作为长期托管浏览器 Agent 方向参考。

## 新窗口协作流程

1. 先读取 `docs/project_memory.md`。
2. 根据“记忆路由”判断任务属于哪个专项。
3. 只读取相关专项记忆，不主动读取无关记忆。
4. 开始前说明目标、允许修改文件、禁止修改文件和验收方法。
5. 执行时不要扩大范围。
6. 结束时按下面格式交接：
   - 本窗口做了什么
   - 改了哪些文件
   - 验证结果
   - 新发现的事实
   - 新增风险
   - 建议写入长期记忆的内容
   - 下一步建议
