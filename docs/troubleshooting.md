# 安装和运行排错

## 1. 双击 start_server.bat 后一闪而过

不要直接关闭窗口。重新双击后看黑色窗口里的第一条 `[ERROR]`。

常见原因：

- 没有安装 Python。
- 网络不能访问 Python 包源，依赖安装失败。
- `.env` 还没填写模型配置。

## 2. 提示没有 .env

这是正常的第一次启动流程。

脚本会从 `.env.example` 复制出 `.env`，你填好 `LLM_PROVIDER`、`LLM_API_KEY`、`LLM_MODEL` 后，再双击 `start_server.bat`。

只想先看本地兜底效果，可以保持：

```env
LLM_PROVIDER=none
```

## 3. 安装依赖很慢或失败

首次启动会创建 `.venv` 并安装后端依赖，需要联网。

可以先换稳定网络，再重新双击 `start_server.bat`。如果仍然失败，把黑色窗口最后 10 行报错复制出来排查。

## 4. 插件提示“后端未连接”

先确认 `start_server.bat` 的窗口还开着。

再打开：

```text
http://127.0.0.1:8000/health
```

如果打不开，说明后端没有启动成功。

如果能打开，但插件仍报错，刷新 BOSS 页面和插件后重试。

## 5. `/health` 里 `api_key_configured=false`

说明模型 API Key 没读到。

检查 `.env`：

```env
LLM_PROVIDER=deepseek
LLM_API_KEY=你的 key
LLM_MODEL=你的模型名
```

不要把 key 写成中文占位文字，也不要多加引号。

## 6. LLM 超时或开场白很模板

常见原因：

- 模型服务商网络不稳定。
- API Key 没额度。
- 代理配置不通。
- 当前岗位 JD 太短，缺少可展开的职责和要求。

建议先用 `LLM_PROVIDER=none` 验证本地快筛，再恢复模型配置。

## 7. 插件提示“没有读到有效 JD”

可能是右侧详情还没加载出来，或者 BOSS 页面结构变化。

处理方法：

1. 左侧点一下该岗位。
2. 等右侧详情出现岗位职责/任职要求。
3. 点击插件里的“继续扫描”。

## 8. BOSS 页面刷新或列表异常

降低单次扫描数量，等页面稳定后继续。不要连续高频点击扫描。

当前项目保留了手动确认发送，是为了降低误发和账号风险。
