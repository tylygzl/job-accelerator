# 阶段 B：HR 新回复半后台发现

更新时间：2026-09-07

## 阶段状态

阶段 B 代码完成，自动回归与固定审核已通过，并已按 Beta 口径收口。真实 BOSS 验收已证明未读发现、会话去重、重复扫描、页面刷新恢复、C0 正常真实未读会话定位、service worker 强制重启恢复和安全不误发。当前只剩 B5-5 依赖新的真实并发事件，继续保持“延期验收、未证明通过”，并在正式扩大分发前补测。

## 阶段目标

在阶段 A 已完成的“用户手动处理当前会话并只填草稿”基础上，增加可靠的新回复发现与待处理队列。

用户保持 BOSS 登录且浏览器仍在运行时，插件可以低频检查消息列表、发现新的 HR 回复、去重加入队列并提醒用户。插件不能抢占正在运行的海投页面，也不能自动发送消息。

## 用户流程

1. 用户登录 BOSS，并正常使用海投或浏览其他页面。
2. 插件在允许检查的消息页或复用的后台标签页中低频读取未读会话。
3. 发现新 HR 回复后，插件只保存必要的结构化摘要并加入待回复队列。
4. popup 徽标或浏览器通知提醒用户有待处理回复。
5. 用户点击“处理回复”后，插件获得任务锁并定位对应会话。
6. 插件重新读取当前聊天 DOM，确认会话与最后消息角色无误。
7. `/chat/reply` 生成草稿并填入输入框。
8. 用户检查后自行发送；插件不点击发送按钮。

## 本阶段范围

- 真实未读会话标记调研与兼容选择器。
- `background.js` 的低频调度、退避和 tab 通信。
- 待回复队列去重、状态更新和刷新恢复。
- popup 徽标或浏览器通知。
- 海投与 HR 检查之间的 task lock 协调。
- 失败可观测、限频和人工接管提示。
- 真实 BOSS 登录态验收与交付记录；朋友测试包需另行授权构建。

## 本阶段不做

- 不自动发送 HR 回复。
- 不绕过 BOSS 登录、验证码、MFA 或风控。
- 不在浏览器关闭后继续运行。
- 不保存 BOSS 密码、Cookie 或完整聊天记录。
- 不让云端后端直接登录或模拟访问 BOSS。
- 不接入完整 RAG 引擎，不扩展面试题功能。
- 不承诺无人值守 24 小时自动沟通。

### B1：未读发现与去重

状态：代码、固定审核与真实未读发现均已通过。2026-08-04 真实页面成功把 2 个带数字角标的未读会话加入队列；其中一个会话包含 2 条未读消息、另一个包含 1 条，插件按会话去重后正确显示“待回复 2”。

- 在真实消息列表确认未读会话的稳定证据。
- 区分 HR 新回复、系统通知、群组消息和用户最后发言。
- 为会话和最新消息分别生成稳定指纹，同一条 HR 回复重复扫描时不重复入队。
- 兼容已有旧队列项，迁移或合并时不重置用户已处理的状态。
- 证据不足时不入队，并在调试状态中说明原因。

### B2：后台调度

状态：代码、固定测试与第一轮独立审核已通过。

- service worker 只负责低频调度和消息传递，不直接读取网页 DOM。
- content script 只在合适页面读取 DOM。
- 海投运行时只记录或延迟检查，不跳转页面。
- 检查失败采用退避，不高频重试。

### B3：队列与提醒

- 复用 B1 的稳定会话与消息指纹，维护队列项的更新和恢复。
- 队列记录 `pending / needs_user / draft_filled` 状态。
- popup 徽标或通知只提示数量，不展示隐私正文。
- 刷新、关闭侧边栏或 service worker 重启后队列可恢复。
- 只有证据充足且后端允许时才填入草稿；证据不足时保守失败并转为 `needs_user`。

## 验收标准

当前 Beta 收口口径：代码、自动回归和固定审核通过；真实 BOSS 已通过无未读检查、历史朋友测试包 PDF 加载、真实未读入队、三扫去重、页面刷新恢复、C0 正常真实未读会话定位、service worker 强制重启恢复、海投中检查不抢当前页的基础证据、用户已回复防重复，以及有效回复只填草稿不自动发送。只有真实未读同时海投场景 B5-5 仍属于延期验收、未证明通过。

1. 阶段 A 的海投和手动 HR 草稿流程回归全部通过。
2. 没有未读 HR 回复时，队列数量不增加。
3. 同一条 HR 回复连续检查三次，只产生一个队列项。
4. 系统消息、职位卡片和用户最后发言不会被当成待回复。
5. 海投运行时，后台检查不会跳转当前搜索页或填输入框。
6. 用户点击处理回复后，海投暂停且 HR 任务获得锁。
7. 当前会话与队列不一致时，不请求后端、不填草稿。
8. 用户已在 HR 后回复时，旧队列项被标记解决或移除。
9. 后端超时、离线或忙碌时，流程在限定时间内结束并提示接管。
10. 刷新页面或 service worker 重启后，未完成队列仍能恢复。
11. popup 徽标或通知数量与待回复队列一致。
12. 插件不会自动点击发送、附件同意、换电话或换微信。
13. 状态面板能显示最近检查时间、结果、失败原因和 request_id。
14. 真实 BOSS 页面至少完成“无未读、一个未读、重复扫描、海投冲突、用户已回复”五类验收。

## 主要风险

- BOSS 未读标记和会话 DOM 可能改版，必须保守失败。
- Manifest V3 service worker 不是常驻进程，只能做事件驱动和低频调度。
- 频繁扫描可能触发平台风控，需要限频、随机抖动和失败退避。
- BOSS 页面切换会话时 URL 可能不变，必须用 DOM 证据确认会话。
- 公开仓库不声明当前在线后端；扩大分发前必须验证私有环境 HTTPS 并轮换凭据。
